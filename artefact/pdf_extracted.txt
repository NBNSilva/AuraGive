Chapter 04 - Artifact 
This chapter presents the key artifacts produced during the development of the AuraGive platform. It 
covers the academic findings derived from the research and development process, the exact locations 
of selected source code within the codebase, and a consolidated test case table used to validate the 
platform's functionality. 
 
4.1 Academic Findings 
 
The development and research conducted for AuraGive produced several significant 
academic findings at the intersection of blockchain technology, natural language processing, 
and trust engineering in the charitable sector. These findings are presented below. 
 
Finding 1 - The Trust Gap Is Structural, Not Incidental 
 
The analysis revealed that the lack of donor trust in existing charitable platforms is not merely a 
perception problem but is embedded in the fundamental architecture of those platforms. Centralised 
fund custody creates an inherent single point of failure for transparency. No amount of reporting can 
fully replicate the cryptographic guarantees offered by a publicly auditable smart contract. This 
validated the core architectural decision of AuraGive: replacing centralised custody with a 
decentralised milestone escrow model on the Polygon blockchain. 
 
 
 
Finding 2 - NLP Is Effective for Pre-Publication Campaign Fraud Detection 
 
Natural Language Processing can serve as a scalable, objective first-line filter for fraudulent charity 
campaigns. Fraudulent campaigns frequently exhibit identifiable linguistic features including 
excessive urgency cues, vague fund usage descriptions, and an absence of concrete logistical details. 
By training a classifier on a curated Kaggle dataset, AuraGive demonstrated that an NLP model can 
assign a meaningful Trust Score before a campaign reaches the public. This shifts fraud detection 
from the individual donor (reactive) to an automated system (proactive). 
 
 
 
Finding 3 - Milestone-Based Escrow Aligns Donor and NGO Incentives 
 
When funds are locked and released only upon completion of defined milestones, both parties benefit. 
Donors are assured their contributions are not irrevocably surrendered at the moment of donation, and 
NGOs are incentivised to execute campaigns in the structured, phased manner they described during 
application. The smart contract effectively makes the campaign's own stated plan a binding 
commitment rather than a persuasive document.

Finding 4 - Polygon Is Appropriate for Charitable Micro Donation Platforms 
 
Testing confirmed that Ethereum mainnet gas fees would render small donations economically 
unviable, as transaction costs could approach the donation amount itself. The Polygon network, with 
dramatically lower gas costs and comparable security via proof-of-stake consensus, was confirmed as 
the appropriate choice for a charitable micro-donation platform targeting Sri Lankan donors. The 
Amoy testnet provided an identical development environment at zero cost. 
 
 
 
Finding 5 - Dark Mode Persistence Requires Root-Level State Management 
 
Managing UI preferences such as dark/light mode at the component level causes the preference to 
reset on every page navigation in a React single-page application. This finding led to the decision to 
lift the isDark state to the root App component and synchronise it with the browser's localStorage 
API, ensuring consistent cross-page persistence. This is a broadly applicable finding for any React 
application requiring persistent UI preferences. 
 
 
 
Finding 6 - AI Score Explainability Increases Donor Confidence 
 
User testing revealed that displaying only a numerical Trust Score was insufficient to build donor 
confidence. When accompanied by a plain-language breakdown (e.g., 'Text Analysis: Passed', 
'Identity: Verified via NGO Registry'), testers reported significantly higher trust in the score's validity. 
This finding underscores the importance of explainability in AI systems deployed in high-stakes 
social contexts an explained score is perceived as credible, while a score without explanation is 
perceived as arbitrary.

4.2 Sample Code 
 
The following code excerpts are selected from the AuraGive codebase to illustrate the key technical 
implementations described throughout this report. Each excerpt is accompanied by an explanation of 
its purpose and significance. 
 
4.2.1 MetaMask Wallet Connection 
 
This function uses the ethers.js v6 BrowserProvider to wrap the browser's injected window.ethereum 
object and request the user's account addresses. The first connected address is stored in global React 
state. If MetaMask is not detected, an alert guides the user to install it. 
 
 
 
 
4.2.2 Persistent Dark Mode with localStorage 
 
The isDark state is initialized with a lazy function reading the saved 'theme' value from localStorage, 
ensuring the correct theme is applied on the very first render. A useEffect hook synchronises any 
changes back to localStorage, making the preference survive page reloads and cross-page navigation. 
 
 
 
 
 
 
 


=== PAGE 7 ===
4.2.3 Donation Confirmation and Transaction State Update 
 
On donation confirmation, a new transaction object is constructed with the campaign title, amount 
(formatted to 2 decimal places), today's ISO date, a 'Confirmed' status, and a simulated 40-character 
blockchain hash. It is prepended to the global transactions array and the user is redirected to the 
Transactions page. 
 
 
 
 
 
4.2.4 AI Trust Score Hover Tooltip with Breakdown 
 
The trust badge is colour-coded based on the numeric score range. A sibling div with CSS group-
hover utility classes is hidden by default (opacity-0 invisible) and becomes visible when the user 
hovers over the badge. The scoreBreakdown string is split on sentence boundaries and rendered as 
individual list items inside the tooltip. 
 
 
 
 
 
 
 
 
 


=== PAGE 8 ===
4.2.5 Admin Milestone Validation Before Submission 
 
Before submitting a campaign, four sequential validations are performed: wallet connection check, 
description minimum-length check (50 characters), document upload check, and a milestone total vs. 
funding goal equality check. If any condition fails, submission is halted with a descriptive alert and 
the function returns early. 
 
 
 
 
4.2.6 Clickable Blockchain TX Hash --> Polygonscan 
 
Each transaction hash is wrapped in an anchor tag whose href is dynamically constructed as 
https://amoy.polygonscan.com/tx/[hash]. The target='_blank' and rel='noreferrer' attributes open the 
link in a new tab securely. The hash is truncated for display, showing the first 10 and last 8 characters.
